# v0.3.0 (rooms over LAN): verification checklist

Everything is on branch `rooms-lan`, **uncommitted**. Automated checks already pass: `npm run typecheck`, `npm test`, `npm run build`, `npm run build:site`, `npm run dist`. A dev-build run against `tools/room-peer` over real UDP already confirmed:
- creating a room from the UI
- the member list and `LAN` badge
- name tags on the right display
- wheel pings reaching the peer
- the 5/s limit and Unlimited
- the 60-ping ceiling
- paused status and bye
- rejecting a mistyped code
- finding a code inside a pasted message

What follows needs your hands, a second device, or a Mac.

## Before you start

- Build and install: `npm run dist`, then run `release/lolPing-Setup-0.3.0.exe` (or `npm run dev`).
- For the one-computer checks, keep a terminal open to run `node tools/room-peer/run.mjs <code>` (fake members; see `tools/room-peer/README.md`).

## 1. Windows ↔ Windows on the same Wi-Fi (or one PC + room-peer)

1. PC A: tray → Room → **Create room**. Expect a "Joined room PING-…" toast, and the Room page showing the code.
2. First time only: Windows asks whether lolPing may use the network. **Allow** it (Private networks).
3. Copy the code to PC B (chat, anything). PC B: copy it, then tray → Room → **Join from clipboard**. Expect "Joined room", and on PC A an "<name> joined" toast.
4. Ping on each PC. Expect the same ping on the other PC at the same relative spot, with the sender's name tag in their colour.
5. Different resolutions or monitor counts: a ping on display 2 lands on the other PC's display 2, or on its primary if it has only one.
6. Rename yourself and pick another tag colour. Expect the other side's member list and tags to update within ~2 s.

## 2. Windows ↔ Mac on the same Wi-Fi (this also covers the macOS spike)

1. Mac: join the Windows room. macOS asks to allow lolPing to find devices on the local network. **Allow** it.
2. Expect both sides to list each other with a `LAN` badge, and pings to go both ways.
3. **If the Mac never sees the PC:** UDP broadcast is blocked for the ad-hoc-signed build. Tell me: the fallback is switching discovery to multicast, a transport-only change.
4. After installing an update on the Mac, check whether macOS asks again (expected limitation of ad-hoc signing).

## 3. Mute, pause, limits (one PC + room-peer is enough)

1. `node tools/room-peer/run.mjs <code> --name Bot --rate 2`. Bot's pings appear with an amber "Bot" tag.
2. Room page → **Mute** next to Bot. Its pings stop. **Unmute**: they come back.
3. **Mute room** (settings or tray). All incoming pings stop, and your own pings still go out.
4. Ctrl+Alt+P (pause). Nothing incoming shows, your row shows `paused`. Ctrl+Alt+P again resumes.
5. `--rate 20` with the limit at 5/s: about 5 pings per second show. Slide to **Unlimited**: all show, and the PC stays responsive (at most 60 on screen).

## 4. Leaving, rejoining, sleep

1. **Leave room**. The other side gets "<name> left" at once.
2. Close lolPing from the tray while in a room. The other side gets "left" (not "disconnected" 15 s later).
3. **Leave**, then join the **same** code again. The other side lists you again, and pings go both ways.
4. With **Rejoin last room on launch** on: quit and start lolPing. It rejoins the same code. After a **Leave**, it does not.
5. Sleep the PC for a minute while in a room, then wake it. The other member reappears within a few seconds without doing anything.
6. Switch Wi-Fi networks (or toggle Wi-Fi off/on) while in a room. Members come back after the network is up.

## 5. Mistakes and limits

1. Type a code with one wrong character. You get "This code looks mistyped." and you don't join.
2. Paste a whole chat message containing a `PING-…` code. It joins that code, never a code made from the words around it.
3. Copy some ordinary text, then tray → Room → **Join from clipboard**. You get "No room code on the clipboard", not a junk room.
4. Correct but unused code: "Waiting for others…", then after 20 s the "check the code" hint.
5. Room full (optional): on the PC that will join, run 8 room-peers aimed at itself (`--host 127.0.0.1`, ports 47475–47482). Then join from that PC. It shows "Room is full" and leaves. Peers only reach the machine named by `--host`.
6. Set a PC's clock 20 minutes off (optional). That PC never appears for the others; their Room page shows "A device trying to join has a clock more than 10 minutes off" instead.

## 6. Look and language

1. Room page in light and dark mode, Windows and Mac: nothing clipped, long names truncate with "…".
2. Switch the language to 简体中文: the Room page, tray submenu and toasts are all translated.

## When everything passes: commit, merge, release

The branch is `rooms-lan` with nothing committed. The spec and plan go in with the code (`docs/superpowers/`).

```bash
git add -A
git commit -m "Add rooms: share pings with friends on the same network"
git switch main
git merge --ff-only rooms-lan
git push origin main
git tag v0.3.0
git push origin v0.3.0
```

The tag starts the Release workflow (Windows installer + Mac disk image).
