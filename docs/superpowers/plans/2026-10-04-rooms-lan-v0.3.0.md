# Rooms over LAN (v0.3.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Members of a lolPing room on the same network see each other's pings at the same relative spot, with name tags. This is milestone M1 of the spec.

**Architecture:**
- Pure shared modules handle the room code, the protocol, validation and colours.
- Main-process modules handle crypto, the replay guard, the rate limiter and display numbering.
- A `RoomManager` state machine talks to transports only through a `Transport` interface. M1 ships one transport, `LanTransport` (Node dgram).
- The overlay reports wheel pings to main and draws name tags. The settings window gets a Room page, the tray a Room submenu.

**Tech Stack:** Electron 44, TypeScript 5.9, Node `crypto` / `dgram`, React 19 + Fluent UI v9, vitest 5.

**Spec:** `docs/superpowers/specs/2026-10-04-room-ping-sharing-design.md` (M1 = §10 "M1 → v0.3.0").

## Global Constraints

- No commits during execution: the user commits and pushes after verifying (the spec and this plan go in with the release).
- No `Co-Authored-By` / "Generated with" lines anywhere.
- No new runtime dependencies in M1. Trystero arrives in M2.
- Room code: `PING-XXXXX-XXXXX`, Crockford alphabet `0123456789ABCDEFGHJKMNPQRSTVWXYZ`, 9 random characters + 1 Luhn mod 32 check character.
- scrypt `N=2^15, r=8, p=1, dkLen=32`, salt `lolping/room/v1`; HKDF-SHA256 infos `msg`, `sig-room`, `sig-pw`.
- Envelope `[0x01][12-byte nonce][AES-256-GCM ciphertext ‖ 16-byte tag]`, AAD = the format byte, ≤1200 bytes.
- `PROTOCOL_VERSION = 1`; UDP port 47474; presence every 2 s; LAN alive 6 s; member removed after 15 s; "Can't reach" after 20 s; full-room settle 3 s; max 8 members; replay window ±10 min / 64 seq.
- Incoming limit 0–20 (0 = Unlimited), default 5. Safety ceiling: 60 pings on screen, 8 overlapping sounds.
- Every user-visible string goes into `src/shared/i18n.ts` in both `en` and `zh-CN`.
- Settings `version` stays 1, and missing keys get defaults.
- Code style: match the surrounding code (2-space indentation, single quotes, terse doc comments, small focused modules).

## Review Focus

1. **Pasting a whole chat message into the join box:** the code is still found, and only the first valid code is used. Pinned in Task 1 (`parseRoomCode` extracts from surrounding text).
2. **A display layout that differs between machines** (sender has 3 displays, receiver 1, different DPI): the ping lands on the receiver's primary at the same fraction. Pinned in Task 4 (`resolveTarget` fallback) and Task 6 (`RoomManager` remote ping mapping).
3. **Sleep/resume or Wi-Fi change while in a room:** the socket is re-bound and members reappear without user action. Pinned in Task 7 (`LanTransport.rebind()` test on loopback).
4. **Name edge cases** (empty, only spaces, 40 characters, emoji, RTL override): the tag stays readable and ≤16 code points. Pinned in Task 2 (`sanitizeName`) and Task 3 (`displayName` normalising).
5. **The global toggle flipped while in a room:** others see `paused` right away, and nothing is sent or shown. Pinned in Task 6 (`setStatusFlags` sends presence immediately; paused drops outgoing and incoming).

### Task 1: Room code

**Files:**
- Create: `src/shared/roomCode.ts`
- Test: `tests/shared/roomCode.test.ts`

**Interfaces:**
- Produces:
  - `ROOM_ALPHABET: string`
  - `makeRoomCode(random9: Uint8Array): string`: canonical form, 10 characters; uses the low 5 bits of each of 9 bytes.
  - `formatRoomCode(canonical: string): string` → `PING-XXXXX-XXXXX`
  - `parseRoomCode(text: string): { ok: true; code: string } | { ok: false; error: 'invalid' | 'mistyped' }`. `code` is canonical.
  - `checkChar(nine: string): string`

- [ ] **Step 1: Write the failing tests**
  - `makeRoomCode` → 10 characters, all in the alphabet, last = `checkChar(first 9)`.
  - Round trip: `parseRoomCode(formatRoomCode(c))` returns `c`.
  - Forgiving input: `ping-7kq4m-2hxtr`-style lower case, spaces, dashes, `O→0`, `I/L→1` all parse to the same canonical code.
  - Every single-character substitution of a valid code gives `mistyped`.
  - Extracting from text: `"join me: PING-XXXXX-XXXXX thx"` → ok; text with no 10-character run → `invalid`.
  - First valid code wins when two are present.
- [ ] **Step 2: Run `npx vitest run tests/shared/roomCode.test.ts`.** Expect FAIL (module missing).
- [ ] **Step 3: Implement.**
  - Luhn mod N with N = 32, factor starting at 2 from the right, as below.
  - Parsing: upper-case, map `O→0`, `I→1`, `L→1`, remove a leading `PING` token, then scan for runs of alphabet characters with spaces/dashes removed *inside* a candidate token group, take 10-character windows, and return the first window whose check passes. If some 10-character window exists but none passes → `mistyped`.

```ts
function luhnCheck(nine: string): number {
  let factor = 2, sum = 0;
  for (let i = nine.length - 1; i >= 0; i--) {
    let addend = factor * ROOM_ALPHABET.indexOf(nine[i]);
    factor = factor === 2 ? 1 : 2;
    addend = Math.floor(addend / 32) + (addend % 32);
    sum += addend;
  }
  return (32 - (sum % 32)) % 32;
}
```

- [ ] **Step 4: Run the test.** Expect PASS.

- [ ] **Step 1: Write the failing tests**
